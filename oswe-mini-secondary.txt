## Before → After dependency upgrade (unchanged -> new)
- scikit-learn: 0.24.1  -> 1.5.2
  - Why: Multiple major releases since 0.24 with performance improvements, bug fixes, new algorithms and Python 3.10+ support. 1.5.x has wheels for modern Pythons and is stable.
- numpy: 1.18.0 -> 2.1.3
  - Why: 1.18 is outdated and lacks many optimizations and security fixes. numpy 2.x provides further optimizations and is available as pre-built wheels for modern Pythons (2.1.3 selected for wide compatibility).
- pandas: 1.1.5 -> 2.3.3
  - Why: pandas 1.1 reached end-of-life; 2.x is the modern line and supports Python 3.10+ with new features and performance improvements.
- matplotlib: 3.3.2 -> 3.9.3
  - Why: 3.9 brings stability improvements, bug fixes and better compatibility with current backends.
- scipy: 1.5.2 -> 1.16.3
  - Why: 1.5 is old; 1.16.3 includes pre-built wheels for modern Python (avoids local source builds) and contains many optimizations and bugfixes.
- pytest: 5.4.3 -> 8.4.2
  - Why: pytest 5 is ancient; modern pytest provides better features, fixtures, warnings, and plugin compatibility.
- fastapi: 0.63.0 -> 0.101.0
  - Why: FastAPI matured substantially. Newer versions improve typing integration, changed API surface in places (review breaking notes if you use advanced FastAPI internals).
- uvicorn: 0.13.3 -> 0.23.2
  - Why: Security fixes, performance improvements, and compatibility with recent ASGI tooling and Python versions.

Notes:
- All pins are exact versions to make the environment reproducible.
- I prioritized picks that offer prebuilt wheels for modern Python to reduce local build steps and avoid heavy native builds.

## Why these choices matter
- Stability + reproducibility: Exact pins help CI and local repeatability.
- Security + compatibility: Latest supported stable versions remove known CVEs and compatibility issues.
- Build reliability: I chose versions with wheel availability for modern Python to avoid large native builds during pip installs (e.g., SciPy).
